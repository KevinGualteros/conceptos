CLOUD COMPUTING

Computación en la nube

La computación en la nube permite aprovisionar recursos informáticos bajo demanda. Esta sección organiza proveedores, servicios, arquitectura, seguridad y costos.

Conceptos fundamentales

Modelos de servicio: IaaS, PaaS y SaaS

IaaS: recursos de infraestructura como máquinas virtuales, redes y discos.

PaaS: plataformas gestionadas que permiten desplegar aplicaciones sin administrar toda la infraestructura subyacente.

SaaS: aplicaciones listas para utilizar a través de un servicio proporcionado por un proveedor.

Regiones y zonas de disponibilidad

Una región es una ubicación geográfica donde el proveedor opera su infraestructura. Una zona de disponibilidad representa una ubicación aislada dentro de una región. Los conceptos exactos varían según el proveedor.

Escalabilidad y alta disponibilidad

La escalabilidad permite aumentar o reducir capacidad. La alta disponibilidad busca mantener el servicio operativo ante fallos, mediante redundancia y mecanismos de recuperación.

Responsabilidad compartida

El proveedor y el cliente tienen responsabilidades diferentes sobre la infraestructura, la configuración, las identidades y los datos. La división depende del servicio contratado.

01. Cómputo y ejecución

Amazon EC2

Qué es: servicio de servidores virtuales configurables.

Cuándo usarlo: aplicaciones que requieren control sobre el sistema operativo, el entorno de ejecución o los servicios instalados.

Conceptos relacionados: AMI, instancia, tipo de instancia, par de claves, EBS, Security Group y User Data.

Comandos habituales

# Listar instancias de la región configurada
aws ec2 describe-instances

# Consultar una instancia específica
aws ec2 describe-instances \
  --instance-ids i-xxxxxxxxxxxxxxxxx

Los comandos requieren AWS CLI configurada y permisos adecuados. Sustituye los identificadores de ejemplo por los reales.

Documentación oficial de EC2 →
AWS Lambda

Qué es: servicio que ejecuta funciones bajo demanda al recibir eventos, sin que el usuario administre directamente los servidores subyacentes.

Cuándo usarlo: procesos orientados a eventos, automatizaciones, integraciones y tareas que encajan en sus límites de ejecución y recursos.

Comparación: EC2 ofrece mayor control del entorno; Lambda abstrae la administración de la infraestructura de ejecución.

02. Almacenamiento

Amazon S3

Qué es: almacenamiento de objetos organizado mediante buckets y objetos.

Usos frecuentes: archivos, copias de seguridad, sitios estáticos, conjuntos de datos y data lakes.

Comandos habituales

# Listar buckets accesibles
aws s3 ls

# Listar objetos de un bucket
aws s3 ls s3://mi-bucket/

# Copiar un archivo al bucket
aws s3 cp archivo.csv s3://mi-bucket/datos/

El nombre del bucket es un ejemplo. Verifica permisos, cifrado y políticas de acceso antes de almacenar datos.

AWS · INTERVIEW PREPARATION

Preguntas frecuentes de AWS

Preguntas técnicas habituales en entrevistas de Cloud, DevOps e infraestructura. Abre cada pregunta para repasar una respuesta directa y sus conceptos clave.

Cloud Entrevistas técnicas Conceptos esenciales

Conceptos generales

¿Qué es AWS?

AWS es una plataforma de servicios de computación en la nube. Ofrece recursos de cómputo, almacenamiento, redes, bases de datos, seguridad, analítica y muchos otros servicios.

En una entrevista: explica qué problema resuelve cada servicio y cómo se integra con los demás, en lugar de limitarte a memorizar nombres.

¿Cuál es la diferencia entre una región y una zona de disponibilidad?

Una región es un área geográfica que contiene infraestructura de AWS. Una zona de disponibilidad es una ubicación aislada dentro de una región.

Diseñar una solución con redundancia entre zonas puede reducir el riesgo de interrupciones causadas por fallos localizados. La estrategia depende de los requisitos de disponibilidad, latencia y costo.

¿Qué diferencia hay entre IaaS, PaaS y SaaS?

IaaS ofrece recursos de infraestructura. PaaS ofrece plataformas administradas para desarrollar o ejecutar aplicaciones. SaaS entrega una aplicación lista para utilizar.

La diferencia central está en cuánto administra el proveedor y cuánto controla el cliente.

Cómputo y aplicaciones

¿Cuál es la diferencia entre EC2 y Lambda?

EC2 proporciona instancias de cómputo virtuales sobre las que puedes configurar el entorno. Lambda ejecuta funciones bajo demanda sin que tengas que administrar directamente los servidores de ejecución.

EC2 encaja cuando necesitas mayor control o un proceso de larga duración. Lambda puede encajar en tareas orientadas a eventos que cumplan sus características y límites de ejecución.

¿Cuál es la diferencia entre ECS y EKS?

ECS es el orquestador de contenedores propio de AWS. EKS es el servicio administrado de Kubernetes de AWS.

ECS puede ser conveniente para equipos que buscan integración directa con AWS. EKS resulta pertinente cuando se requiere Kubernetes y su ecosistema. La decisión depende de las capacidades operativas del equipo y de la arquitectura.

¿Qué significa serverless?

Serverless es un modelo en el que el proveedor administra gran parte de la infraestructura subyacente. El usuario sigue teniendo responsabilidades sobre código, configuración, permisos, seguridad y costos.

No significa que no existan servidores; significa que el cliente no administra directamente una parte importante de ellos.

Almacenamiento y bases de datos

¿Cuál es la diferencia entre S3, EBS y EFS?

S3 almacena objetos identificados mediante claves dentro de buckets.

EBS proporciona almacenamiento de bloques para instancias compatibles.

EFS ofrece un sistema de archivos compartido gestionado para clientes compatibles.

La elección depende de cómo la aplicación accede a los datos: mediante objetos, bloques o archivos.

¿Cuál es la diferencia entre RDS y DynamoDB?

RDS es un servicio administrado para motores de bases de datos relacionales. DynamoDB es una base de datos NoSQL con modelos de clave-valor y documentos.

RDS suele ser apropiado cuando el modelo relacional y las consultas SQL son importantes. DynamoDB puede ser adecuado para patrones de acceso conocidos que aprovechen su modelo de datos.

¿Qué significa que un servicio sea administrado?

Significa que el proveedor gestiona determinadas tareas operativas del servicio, como parte del mantenimiento o la infraestructura subyacente.

No elimina la necesidad de administrar permisos, monitoreo, diseño, respaldos cuando corresponda, costos y recuperación. El alcance exacto depende del servicio.

Redes y seguridad

¿Qué es una VPC?

Una Amazon VPC es una red virtual donde se pueden definir rangos de direcciones IP, subredes y reglas de enrutamiento para organizar recursos de AWS.

En una entrevista, menciona también las tablas de rutas, los Internet Gateways, los NAT Gateways y los controles de tráfico cuando sean pertinentes al caso.

¿Cuál es la diferencia entre un Security Group y una Network ACL?

Un Security Group controla tráfico asociado a interfaces de red o recursos compatibles y es stateful.

Una Network ACL aplica reglas a nivel de subred y es stateless: deben contemplarse explícitamente las reglas de entrada y salida.

¿Cuál es la diferencia entre Internet Gateway y NAT Gateway?

Un Internet Gateway permite la conectividad entre una VPC e Internet cuando el direccionamiento, las rutas y los controles de seguridad están correctamente configurados.

Un NAT Gateway permite que recursos en subredes privadas inicien conexiones salientes a redes externas sin requerir que dichos recursos tengan conectividad entrante directa desde Internet.

¿Qué es IAM y qué significa mínimo privilegio?

IAM administra identidades y permisos de acceso a recursos de AWS. El principio de mínimo privilegio consiste en otorgar únicamente los permisos necesarios para realizar una tarea.

Para workloads y automatizaciones, considera roles y credenciales temporales cuando la arquitectura lo permita, en lugar de distribuir claves permanentes.

Operación y arquitectura

¿Para qué sirve CloudWatch?

CloudWatch permite trabajar con métricas, logs y alarmas para monitorear recursos y aplicaciones.

Un caso habitual es definir una alarma basada en una métrica y vincularla con una acción o notificación apropiada.

¿Para qué sirve CloudTrail?

CloudTrail registra eventos relacionados con la actividad de API en AWS y ayuda a investigar quién realizó una acción, cuándo ocurrió y qué operación se ejecutó, según los datos disponibles del evento.

¿Cómo se puede reducir el costo de una arquitectura AWS?

Empieza midiendo el consumo y relacionándolo con el uso real. Dimensiona los recursos adecuadamente, elimina recursos sin uso, revisa el almacenamiento y el tráfico, y evalúa opciones de precios según el patrón de carga.

Utiliza presupuestos y alertas para detectar desviaciones. Antes de eliminar o modificar recursos, verifica dependencias, impacto y requisitos de recuperación.

¿Qué es Infrastructure as Code en AWS?

Infrastructure as Code permite definir recursos de infraestructura mediante archivos versionables y automatizar su creación o modificación.

AWS CloudFormation es una herramienta nativa de AWS. Terraform también permite administrar infraestructura en AWS y otros proveedores.

¿Cómo investigarías una aplicación que no responde?

Primero delimita el fallo y su alcance. Después verifica DNS, conectividad, rutas, puertos, controles de seguridad, estado del balanceador, salud de instancias o contenedores, logs, métricas y cambios recientes.

No cambies varios componentes al mismo tiempo sin una hipótesis: recopila evidencias, valida cada paso y registra la causa y la solución.

VERSION CONTROL

Git y GitHub

Control de versiones, ramas, commits, resolución de conflictos, colaboración mediante pull requests y automatización asociada al repositorio.

Comandos esenciales

# Revisar el estado del repositorio
git status

# Preparar cambios
git add .

# Crear un commit
git commit -m "Describe el cambio"

# Consultar el historial
git log --oneline

# Descargar y combinar cambios remotos
git pull

# Enviar commits al remoto
git push
¿Cuál es la diferencia entre Git y GitHub?

Git es un sistema de control de versiones. GitHub es una plataforma para alojar repositorios Git y facilitar colaboración y automatización.

¿Qué diferencia hay entre merge y rebase?

Merge integra historiales creando una unión de ramas. Rebase reaplica commits sobre otra base y puede cambiar sus identificadores. Rebasar ramas compartidas exige precaución.

AUTOMATION

GitHub Actions

Automatización de flujos de trabajo mediante archivos YAML almacenados en el repositorio.

Ejemplo mínimo de workflow

name: Validar cambios

on:
  push:
  pull_request:

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - name: Descargar repositorio
        uses: actions/checkout@v4

      - name: Validar archivos
        run: |
          test -f index.html
          test -f style.css
          test -f script.js

Este workflow solo comprueba la existencia de los tres archivos. Los pasos de pruebas y despliegue deben adaptarse a las necesidades del proyecto.

CONTAINERS

Docker

Herramientas para construir imágenes y ejecutar aplicaciones en contenedores.

Comandos esenciales

# Construir una imagen
docker build -t mi-app:local .

# Ejecutar un contenedor
docker run --name mi-app-container -p 8080:80 mi-app:local

# Listar contenedores en ejecución
docker ps

# Ver logs
docker logs mi-app-container

# Listar imágenes
docker images

# Detener un contenedor
docker stop mi-app-container
Imagen vs. contenedor

Una imagen es una plantilla inmutable por capas. Un contenedor es una instancia ejecutable creada a partir de una imagen.

Dockerfile, redes y volúmenes

El Dockerfile define cómo construir una imagen. Las redes conectan contenedores y los volúmenes permiten persistir o compartir datos.

ORCHESTRATION

Kubernetes

Sistema de orquestación de contenedores. Permite declarar el estado deseado de las aplicaciones y coordinar su ejecución.

Comandos esenciales

# Listar pods
kubectl get pods

# Listar deployments
kubectl get deployments

# Inspeccionar un recurso
kubectl describe pod nombre-del-pod

# Consultar logs
kubectl logs nombre-del-pod

# Aplicar una configuración declarativa
kubectl apply -f deployment.yaml

# Consultar eventos
kubectl get events
Pods, Deployments y Services

Pod es la unidad de ejecución básica; Deployment administra réplicas y actualizaciones de aplicaciones sin estado; Service proporciona un punto de acceso estable a un conjunto de pods.

ConfigMaps, Secrets y probes

ConfigMaps y Secrets permiten suministrar configuración. Las probes permiten comprobar diferentes aspectos del estado de los contenedores. Los Secrets requieren controles de acceso y medidas de protección apropiados.

Ingress, Gateway, HPA y RBAC

Son conceptos relacionados con exposición de aplicaciones, escalado automático y control de permisos. Su configuración depende de la versión y de los componentes instalados.

INFRASTRUCTURE AS CODE

Terraform

Herramienta declarativa de infraestructura como código que permite administrar recursos mediante providers, resources, modules y state.

Comandos esenciales

# Inicializar directorio y providers
terraform init

# Validar sintaxis y configuración
terraform validate

# Mostrar el plan de cambios
terraform plan

# Aplicar la configuración revisada
terraform apply

# Consultar el estado
terraform state list
Provider, resource y module

Provider conecta Terraform con una plataforma. Resource declara un objeto administrado. Module agrupa y reutiliza configuraciones.

State y backend

El state relaciona la configuración con los objetos administrados. Un backend determina cómo y dónde se almacena ese estado. Debe protegerse y coordinarse el acceso en equipos.

LINUX · INTERVIEW PREPARATION

Preguntas frecuentes de Linux

Comandos, permisos, procesos, servicios y solución de problemas.

¿Cuál es la diferencia entre un proceso y un servicio?

Un proceso es una instancia en ejecución de un programa. Un servicio es una función del sistema que normalmente se administra mediante mecanismos como systemd.

¿Qué hacen chmod y chown?

chmod modifica permisos de acceso; chown cambia el propietario y, cuando corresponde, el grupo de un archivo o directorio.

NETWORKING · INTERVIEW PREPARATION

Preguntas frecuentes de Networking

Conceptos y escenarios habituales para entrevistas de redes, infraestructura y Cloud.

¿Cuál es la diferencia entre TCP y UDP?

TCP establece una conexión y proporciona mecanismos de entrega fiable y ordenada. UDP transmite datagramas sin ofrecer las mismas garantías de entrega y orden. El protocolo adecuado depende de la aplicación.

¿Qué hace DNS?

DNS permite consultar registros asociados a nombres de dominio, como direcciones IP y otros datos utilizados por aplicaciones y servicios.

¿Qué revisarías si un servicio no es accesible?

Verifica resolución de nombres, direccionamiento, rutas, reglas de firewall, puerto de destino, estado del servicio y registros de diagnóstico.

FULL STACK · INTERVIEW PREPARATION

Preguntas frecuentes de Full Stack

Fundamentos de frontend, backend, APIs, persistencia y calidad de software.

¿Cuál es la diferencia entre frontend y backend?

Frontend se ocupa de la interfaz y de la interacción del usuario. Backend implementa lógica del servidor, reglas de negocio, integración de datos y servicios expuestos mediante interfaces.

¿Qué es una API REST?

Es una interfaz que aplica restricciones de estilo REST para exponer recursos y operaciones mediante una interacción cliente-servidor. En la práctica, las APIs web REST suelen utilizar HTTP.

DATA · INTERVIEW PREPARATION

Preguntas frecuentes de Data

Preguntas sobre SQL, almacenamiento analítico, pipelines y visualización.

¿Cuál es la diferencia entre ETL y ELT?

ETL transforma los datos antes de cargarlos en el destino. ELT carga primero los datos y realiza transformaciones dentro de la plataforma de destino, cuando su arquitectura y capacidades lo permiten.

¿Cuál es la diferencia entre OLTP y OLAP?

OLTP se orienta a operaciones transaccionales de una aplicación. OLAP se orienta a consultas analíticas sobre datos, agregaciones y análisis de tendencias.

SECURITY · INTERVIEW PREPARATION

Preguntas frecuentes de seguridad

Identidad, autorización, protección de secretos y cifrado.

¿Cuál es la diferencia entre autenticación y autorización?

Autenticación verifica la identidad presentada. Autorización determina qué acciones puede realizar esa identidad sobre determinados recursos.

¿Qué significa mínimo privilegio?

Otorgar solo los permisos necesarios para una tarea y reducir accesos innecesarios o excesivos.

OBSERVABILITY · INTERVIEW PREPARATION

Preguntas frecuentes de observabilidad

Métricas, logs, trazas, alertas y diagnóstico de incidentes.

¿Cuál es la diferencia entre métricas, logs y trazas?

Las métricas representan valores medibles a lo largo del tiempo. Los logs registran eventos. Las trazas siguen el recorrido de una operación a través de componentes.

API · INTERVIEW PREPARATION

Preguntas frecuentes de APIs y testing

Pruebas, contratos, solicitudes HTTP y validación de respuestas.

¿Cuál es la diferencia entre GET y POST?

GET se utiliza para recuperar una representación de un recurso. POST suele utilizarse para enviar datos para su procesamiento o crear recursos según las reglas de la API.

¿Para qué sirve Postman?

Permite construir solicitudes HTTP, gestionar colecciones, configurar variables y validar respuestas de APIs durante el desarrollo.
